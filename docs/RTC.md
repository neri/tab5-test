# RTC（RX8130CE）

> 索引: [`../DESIGN.md`](../DESIGN.md)

`rtc`コマンドは、ボードI2Cバス（SDA31/SCL32）のアドレス`0x32`にあるEpson RX8130CEを
読み書きし、機能を検査する。引数なしでカレンダーと拡張／フラグ／制御レジスタを表示し、
`rtc set <YYYY-MM-DD> <HH:MM:SS>`で時刻を設定、`rtc regs`でレジスタ`0x10`〜`0x1F`を
そのまま16進ダンプ、`rtc test`で検査手順を実行する。ドライバーは`src/rtc.rs`である。

RX8130CEにはIDレジスタがない。したがってI2C ACKだけでは、そのアドレスに応答したのが
本当にRX8130CEかを判定できない。`src/rtc.rs`はレジスタ内容自体を判定基準にする。
BCDの各ニブルが0〜9であること、時分秒・日・月が暦として成立する範囲にあること、
週レジスタ（`0x13`）の立っているビットが正確に1本であることを確認し、満たさない場合は
`Error::InvalidTime`を返す。週レジスタはEpson系RTCと同じone-of-seven形式（bit 0が日曜、
bit 6が土曜）で、数値ではなくビット位置である。

読み出しはレジスタポインタの自動インクリメントを利用し、`0x10`から7バイトを1
トランザクションで読む。RX8130CEは読み出し中にカウンタを凍結しないため、
bit-bangバスでの7バイトの読み出し中に桁上がりが起こり得る（23:59:59が翌分の
23:59:00として読める）。`read_datetime`は読み出し後に秒カウンタを再読し、変化していれば最大3回まで
読み直す。

時刻書き込みは`CTRL0`（`0x1E`）の`STOP`をセットしてカウンタを止め、`0x10`から7バイトを
書き、`STOP`を元に戻す。7バイトの途中で桁上がりが入らないようにするための手順である。
書込みが失敗した場合でも`STOP`の復帰は必ず実行する。時計を止めたまま放置する方が、
書き途中のカレンダー（呼び出し側が再実行できる）より悪いためである。週レジスタは
引数ではなく日付から`weekday_from_date`（Zellerの公式）で計算した値を書く。日付と
矛盾する曜日を書き込む意味がないためである。年はRX8130CEが2桁しか持たず世紀ビットも
ないため、この実装が2000年代（2000〜2099）と決めている。書込み成功後は電圧低下フラグ
（`FLAG`の`VLF`）をクリアする。このフラグの意味は「カレンダーの内容は信用できない」で
あり、それが今まさに成立しなくなったからである。アラームフラグ・タイマーフラグは
それを設定した側のものなのでクリアしない。フラグは該当ビットへ0を書くとクリア、1を
書くと保持されるため、`clear_flag`はread-modify-writeではなく対象ビットの補数を書く。

書き込むレジスタはカレンダーカウンタ（`0x10`〜`0x16`）とフラグ（`0x1D`）だけである。
`CTRL1`（`0x1F`）はバックアップ電圧選択と充電許可を保持しており、主電源を切った状態で
時計が動き続けるかどうかを決めるため、表示のためだけに読み、書き換えない。`CTRL0`の
`STOP`は上記の書込み中だけの例外である。

`rtc test`は、証明する内容が軽いものから重いものへ順に並べた検査である。

1. アドレス`0x32`がACKするか（デバイスが存在するか、バス障害でないか）
2. 拡張・フラグ・制御レジスタの内容と、そこで立っているビットの名前（`VLF`／`AF`／
   `TF`／`UF`、`AIE`／`TIE`／`UIE`／`STOP`／`TEST`）。`STOP`が立っていればカウンタが
   止められているため失敗として数える。`VLF`は警告として表示する。一度も時刻を設定
   していない基板では正常な状態であり、失敗数には数えない
3. カレンダーが暦として成立する日時か。成立する場合、週レジスタの曜日が日付から
   計算した曜日と一致するかも確認する（週レジスタは日付から導出された値ではなく独立した
   カウンタなので、両方読めて食い違うことがあり得る）
4. 秒カウンタの桁上がり間隔。最初の桁上がりで秒境界へ同期し、次の桁上がりまでの時間を
   `membench::cycles()`と`startup::cpu_hz()`で測る。1000 ms±50 msを合格とする。
   ここだけがレジスタファイルではなく32.768 kHz発振器の動作を観測する検査である
5. 更新フラグ（`UF`）。`UF`をクリアし、再びセットされるまでの時間を測る。RX8130CEは
   拡張レジスタの`USEL`が秒更新を選んでいる間、毎秒`UF`をセットする。`USEL`が分更新を
   選んでいる場合は1分待つ意味がないため、この検査は省略する

検査は桁上がりを2回待つため約3秒かかる。この間コマンドはフレームループへ戻らないので、
出力は完了時に一括で表示される。走査線出力（DW-GDMA）は独立して動き続けるため、待機中も
画面は保持される。書き込むのは`UF`のクリアだけであり、正しい時刻を保持している時計は
検査後も正しいままである。

アラーム（`0x17`〜`0x19`）とウェイクアップタイマー（`0x1A`〜`0x1B`）、`/INT`出力による
起動については、この経路では検査しない。レジスタダンプに値は現れるが、設定も割り込み
配線の確認も行わない。
