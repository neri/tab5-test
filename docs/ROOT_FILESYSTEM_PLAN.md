## 確定した仕様

PSRAM上の8 MiB RAMディスクを`/tmp`ではなく`/`へ読み書き可能でマウントする。
RAMディスクは起動時に毎回FAT16で作り直すため、`/`以下に書いた内容はリセットで消える。

```text
/
├── tmp/             一時ファイルを置く既定の場所
└── vol/             外部ボリューム専用の予約名前空間
    ├── sd0p1/       microSD（読み取り専用）
    └── usb0p1/      USB Mass Storage（読み取り専用）
```

- `/`はRAMディスク全体であり、`/tmp`と`/vol`以外には通常どおりファイルと
  ディレクトリを作れる
- `/tmp`に一時ファイルを置くことは運用ポリシーであって、`/tmp`以外への書き込みを
  禁止するアクセス制御ではない
- `/tmp`のディレクトリエントリそのものは削除、改名、置換を禁止する。配下は通常どおり
  読み書きできる
- `/vol`はVFS専用の予約名前空間とする。ディレクトリそのものと、外部媒体がマウント
  されていない直下への作成、削除、改名、移動を禁止する
- SDとUSBは従来どおり`/vol/<volume-name>`へ読み取り専用でマウントする
- RAMディスクは起動中の恒久マウントで、`umount /`を禁止する。`mount ram`は既に
  `/`へマウント済みと報告する
- シェルの初期カレントディレクトリと`cd`の引数なしは従来どおり`/`とする
- ダウンロード中の`.part`は完成予定ファイルと同じディレクトリに置く。将来ほかの
  ファイルシステムを読み書き可能にしたときも、確定操作を同一ファイルシステム内の
  renameに保つためである
- RAMディスクの確保、format、初期ツリー作成、`/`へのマウントの失敗はpanicする。
  読み取り専用の外部媒体だけで縮退運転する経路は持たない

## Stage 1: VFS

現在のVFSは`/`を合成ノードとして予約し、ルートへのマウントを拒否する。これを
ルートボリュームを許す形へ変える。パス解決は既に最長マウントポイント一致なので、
`/vol/usb0p1`が`/`より優先される規則は維持できる。

ディレクトリ一覧は、ボリューム自身のエントリと、その直下にある子マウントを合成する。
同名なら子マウントを優先して`mount`と表示し、アンマウント後に隠れていた実体が現れる
構成は予約された`/vol`では作れないようにする。

予約パスへの変更は専用の`ReservedPath`エラーで拒否する。読み取り専用媒体への書き込みは
従来どおり`ReadOnly`であり、予約名前空間の拒否と混同しない。

## Stage 2: 起動時の初期ツリー

formatter直後の媒体に`/tmp`と`/vol`を作り、検証用の`README.TXT`、
`Hello World.txt`、`CHAIN.TXT`を`/tmp`へ置く。検証ファイルは従来どおりFATライブラリの
writerを通さず、FATとディレクトリエントリを直接構築する。

初期化順は次で固定する。

```text
RAMディスク領域をclaim
→ FAT16 format
→ /tmp、/vol、/tmp以下の検証ファイルを構築
→ RAMディスクを/へ恒久マウント
→ 通常起動
```

どこかで失敗した場合はUARTへ原因を記録してpanicする。

## Stage 4: 実機受入

- 起動後の`mounts`で`ram on /`が読み書き可能として出る
- `ls /`に`tmp`と`vol`が出て、検証ファイルは`ls /tmp`にだけ出る
- `/NOTE.TXT`への書き込み、追記、読み出し、削除が成功する
- `/tmp`配下の通常操作が成功し、`rm`／`rmdir`／`mv`で`/tmp`自体は変更できない
- `/vol`と未マウントの`/vol/name`への作成、削除、改名が`reserved path`で失敗する
- SDとUSBが従来どおり`/vol`以下へ現れ、一覧、読み出し、自動アンマウントが成功する
- `umount /`が拒否され、`mount ram`が既にルートにあることを報告する
- TFTP／HTTPの`.part`と完成ファイルが保存先ディレクトリにあり、成功時は`.part`が残らない
