# ファイルシステム（VFS、FAT、マウント）

> 索引: [`../DESIGN.md`](../DESIGN.md) ／ 段階分けと実機での判断:
> [`FILESYSTEM_PLAN.md`](FILESYSTEM_PLAN.md) ／ 下層のブロックI/O:
> [`STORAGE.md`](STORAGE.md)

パス名でファイルを読み書きできるところまでを実装しています。読み出しは
FAT12/16/32とexFAT、書き込みはRAMディスクを載せた`/`全体です。シェルはカレント
ディレクトリを持ち、相対パスを解決してからVFSへ渡します。USB Mass Storageは
挿抜に合わせて自動でマウント・アンマウントします。

## 名前空間

Unix型の単一ツリーと固定マウントポイントで組み合わせます。ドライブ番号は
公開APIに出しません。パスは常に絶対パスです。

```text
/
├── tmp/             一時ファイル用（読み書き可、リセットで消える）
└── vol/             外部ボリューム専用の予約名前空間
    ├── sd0p1/       microSDのMBR primary entry 1（読み取り専用）
    ├── sd0p2/       同じカードの別entry。同時にマウントできる
    ├── usb0p1/      1台目のUSB Mass Storage（読み取り専用）
    └── usb1p1/      2台目のUSB Mass Storage
```

`usbM`はUSBホストレジストリが接続時に振る番号で、**そのデバイスが繋がっている
間は取り上げません**（[USB.md](USB.md)）。2本挿したうちの1本目を抜いても2本目の
番号は動かないので、触っていないデバイスのマウントは壊れません。USB Addressは
列挙のたびに再割り当てされ抜去後に別デバイスへ再利用されるので、マウントが
覚えておく名前には使えません。バス上の位置も、抜くと後ろが繰り上がるので同じく
使えません。

ただし番号も**同一性ではありません**。デバイスが去れば番号はいずれ他へ回ります。
媒体の同一性は下記のfingerprintで確認します。

マウントポイントは名前から機械的に決まります。取り外せる媒体は`/vol/<name>`、
RAMディスク（`ram`）は`/`です。呼び出し側が場所を選べないのは、同じ
ボリュームがマウントの仕方によって別のパスから見えることを避けるためです。

RAMディスクは起動ごとにフォーマットし直され、リセットで消える揮発領域です。
そのルートに通常のFAT16ディレクトリとして`/tmp`と`/vol`を作ります。`/tmp`へ
一時ファイルを置くのはUnixと同じ運用ポリシーで、`/tmp`以外への書き込みを止める
アクセス制御ではありません。`/NOTE.TXT`や`/home/file`も作れます。

RAMディスクは起動時に`/`へ恒久マウントし、`umount /`を`reserved path`で拒否します。
`mount ram`をもう一度実行すると`already mounted`です。RAMディスクの初期化、初期ツリー
作成、ルートマウントのどれかが失敗した場合は縮退運転せずpanicします。

### ボリュームのディレクトリと子マウントを合成する

`/`と`/vol`はRAMディスク上の実ディレクトリです。その一方、`/vol/sd0p1`などの
末端は外部ボリュームのマウントポイントであり、RAMディスク上に対応する
ディレクトリエントリを作りません。`ls`は開いたディレクトリのエントリとマウント表の
直下要素を合成します。同名なら子マウントを優先します。

```text
> ls /
tmp  vol
> ls -l /
dir          (no time)    tmp
dir          (no time)    vol
2 entries
> ls /vol
sd0p1  usb0p1
```

`/vol`は外部媒体が無くても常に存在します。外部媒体を抜くとその末端マウントだけが
消え、`/vol`は残ります。

**マウントポイントの要素を合成する**のは、一覧が見せた名前をそのまま
`cd`に渡せるようにするためです。以前は`/`が`sd0p1`（マウントポイントの最後の
要素）を並べていましたが、そのボリュームが答えるのは`/vol/sd0p1`だけなので、
一覧が出す唯一の名前が使えない名前でした。カレントディレクトリを入れて初めて
表面化した矛盾です。

一覧はほかのディレクトリと同じく名前順です（下記「`ls`の表示」）。同じノードの
下に2つ以上のボリュームがある場合、そのノードは1回だけ出ます。

`/tmp`のディレクトリエントリ自体と、`/vol`および未マウント部分の`/vol/...`は
VFSの予約パスです。削除、改名、置換、作成を`reserved path`で拒否します。`/tmp`の
配下は通常どおり変更できます。マウント済みの`/vol/<name>/...`はその外部ボリュームへ
解決され、従来どおり`read-only`です。

## `ls`の表示

既定は**名前だけを名前順で桁詰め**します。`-l`で種別・サイズ・更新日時が付いた
1行1エントリになり、末尾に件数が出ます。`-a`はFATがサブディレクトリごとに持つ
`.`と`..`を含めます。`-la`のようにまとめて書けます。

桁詰めの規則は実物の`ls`に合わせてあります。**列幅は列ごと**（全体の最長ではなく
その列の最長）で、名前は**列を上から下へ**埋めます。1つ長い名前があるだけで全列が
離れてしまうのを避けるためと、名前順に並んだものを縦に読めるようにするためです。
1行はコンソール幅（156桁）に**収まりきらない手前**で折り返します。ちょうど156桁の
行は折り返した上で行が終わり、空行が1行残るためです。桁数は`chars().count()`ではなく
`font::console::cell_count`で数えます（[`CONSOLE_SHELL.md`](CONSOLE_SHELL.md)）。

並び順はASCIIの大文字小文字を無視し、同じなら大文字小文字で決めます。
`README.TXT`と`readme.txt`が隣り合うようにするためで、バイト順のままだと
小文字の名前が別の塊に離れて「並んでいない」ように見えます。

ソートのためにエントリは**いったん全部集めてから**表示します。ディレクトリは媒体上の
並び順で届くので、流しながら名前順にすることはできません。バッファはPSRAMヒープ上に
エントリ1つあたり`String`1つです。

## USBの自動マウント

USB Mass Storageは**挿すと勝手にツリーに出て、抜くと勝手に消えます**
（`src/app/automount.rs`）。SDは対象外で従来どおり明示操作、RAMディスクは起動時の
恒久マウントです。

かつては「ツリーに現れるボリュームは必ず誰かがマウントを要求した結果」と決めて
いました（[`FILESYSTEM_PLAN.md`](FILESYSTEM_PLAN.md)）。あの方針の目的は、
起動媒体の探索順のような**判断**が「いつの間にかマウントされていた」に紛れ込むのを
防ぐことでした。自動マウントはその判断をしません。挿さっているものを見えるように
するだけなので、目的を損ないません。代わりに次を守ります。

- **`automount off`で完全に止まります。** 止めれば従来どおり`mount`と`umount`
  だけになります
- **結果を記録します。** 通常画面ではマウント・アンマウントのたびにコンソールとUARTへ
  `automount: `で始まる1行を出します。入力途中の行があれば、いったん退避して
  出力の下に戻します（[CONSOLE_SHELL.md](CONSOLE_SHELL.md)）。起動画面が表示を所有して
  いる間だけは、白い画面を壊さないよう同じ行をUARTだけへ出します
- **媒体同一性の仕組みを迂回しません。** 自動マウントもシェルの`mount`と同じ
  `files::attach`を通り、fingerprintを取り、新しいgenerationを振ります。抜いて
  挿し直したものは**別のマウント**で、古いハンドルは復活しません
- **利用者の操作を取り消しません。** 1台のデバイスに対して自動マウントを試すのは
  接続時の1回だけです。その後`umount`したものは、そのデバイスを物理的に抜いて
  挿し直すまでマウントされたままにはなりません

### 何をどこまで自動でマウントするか

新しく現れたデバイスのMBR primary entryを順に試し、**読めるファイルシステムが
載っていたものを全部**マウントします。載っていない entry（Windowsが作る回復
パーティション等）は`Vfs::mount`がブートセクタを見て断るので、そこで静かに
飛ばします。1つもマウントできなければ`no readable filesystem`と1行出します。
パーティション表の無い媒体（superfloppy）はマウント先の名前が作れないので、
その旨を出して飛ばします。

電源投入時に既に挿さっているデバイスも対象です。白い起動画面がUSB初回探索を終えると、
同じ`AutoMount` instanceを`pending`が無くなるか4,000 ms budgetを使い切るまで進めます。
Escapeで起動をキャンセルした場合もinstanceとdeadlineをConsole loopへ引き継ぎます。

### いつ走るか

`UsbHost::topology_epoch`（[USB.md](USB.md)）が進んだフレームだけです。毎フレーム
比較するのは整数1つで、バスには触れません。実際の突き合わせは`app::run`の
ループが**コマンド実行と同じ位置で**行います。ボリュームを開くのはバスI/Oと
FAT解析で数十msかかり得るので、`InputManager::service`（コンソールの再描画が
待っている側）には置けません。

### 立ち上がるまで待つ

デバイスは列挙に答えた時点でバスにbindされますが、**logical unitが読み出しに
答えるのはその後**です。大容量のUSBメモリやカードリーダーは内部初期化に数秒
かかることがあります。`UsbMscBlockDevice::probe`はTEST UNIT READYを1回だけ
撃って諦めるので、接続の瞬間に1回聞くだけでは取りこぼします。

そこで、開けなかったデバイスは250 msおきに聞き直し、**4,000 ms**まで待ちます。
この数字は起動シーケンスがMSCのready待ちに使っているもの（`STORAGE.md`）と
同じで、聞くタイミングが違うだけの同じ問いだからです。budgetを使い切ったら
`did not become readable`と1行出して諦めます。

### 答えなかったものは聞き直す

同じbudgetは**パーティションごとのマウント失敗**にも効きます。転送が1回失敗して
recoveryで復帰するのはこのバスの既知の性質で（[`USB_WRITE_STABILITY_PLAN.md`](USB_WRITE_STABILITY_PLAN.md)）、
それに対する既定の答えは「呼び出し側が後で再試行する」です（下記「rescanを
跨いでもマウントは生き残る」）。1回タイムアウトしたREAD CAPACITYをそのentryの
最終回答にすると、物理的に挿し直すまでそのパーティションはツリーに出てきません。

再試行する／しないは失敗の種類で決めます。

| 失敗 | 扱い |
| --- | --- |
| デバイスが開けない（`device not present`、`not ready`、`device error`、`temporarily unavailable`） | 答えが取れていないので再試行 |
| 読めるファイルシステムが無い | 答えである。静かに飛ばす |
| 媒体が入れ替わった／持ち去られた | 答えである。次の突き合わせが扱う |

`Vfs::mount`はfingerprint、ブートセクタの読み出し、ボリュームのopenでそれぞれ
デバイスを解決し直すので、**そのどれもが失敗中の転送に当たり得ます**。答えたentryは
マウントされたまま残るので、再試行に残るのは答えなかったentryだけです。budgetを
使い切って初めて`automount: usb1p1: <理由>`と1行出します。

**この待ちと再試行が無いと、間欠的に「挿したのに`/vol`に出てこない」ことに
なります。** 大容量の媒体ほど立ち上がりが遅く転送も不安定になりやすく、
大容量の媒体はexFATでフォーマットされていることが多いので、exFAT固有の問題に
見えます。

### 開いたままのファイルハンドル

`fsopen`だけが、ファイルをコマンドとコマンドの**あいだ**開いたままにします。
ほかのコマンド（`cat`など）は開いたものを戻る前に必ず閉じるので、これが無いと
「ドライブを抜いた瞬間にハンドルが開いている」状態をコンソールから作れません。
自動アンマウントの定義（マウントが消え、その上のハンドルは以後失敗する）を
実際に確かめられるようにするための経路です。

`fsopen`の一覧が出す`live`／`stale`が要点です。ハンドルはボリュームが
マウント表から消えた瞬間に`stale`になり、**元には戻りません**。同じUSBメモリを
挿し直しても新しいgenerationになるためで、それがgenerationの目的そのものです。
判定はマウント表を見るだけなので、媒体が物理的に無くてもバス通信なしで答えます。

`stale`なハンドルもVFSの開ファイル表のスロット（`MAX_OPEN_FILES` = 4）を
占め続けます。自動アンマウントは`fsverify`と同じくハンドルに触らずマウントだけを
落とすためで、スロットを返すには`fsclose`します。

### 取り外しは強制アンマウント

`umount`は開いているファイルがある間`Busy`で断りますが、それは媒体がまだ
そこにあるから言える話です。物理的に抜かれた後は戻る先が無いので、自動
アンマウントは開いているファイルを見ずにマウントを落とします。残ったハンドルは
以後失敗します。`fsverify`が`DISCONNECTED since mount`でやることと同じで、
根拠も同じ`ConnectionEpoch`です。

判定はconnection epochが進んだかどうかだけで、バス通信はしません。**単に応答
しないデバイスは落としません**。応答しないことは抜かれた証拠ではなく、再スキャンで
同じ媒体がそのまま戻ってくることが多いためです（下記「rescanを跨いでもマウントは
生き残る」）。

### マウント時にボリュームを開く

マウント時にボリュームを一度開いて捨てます。無駄ではなく、「このパーティションには
読めるファイルシステムが無い」ことをマウント時に知るか、動かないマウントが
表に残ったまま最初の`ls`で知るかの違いです。自動マウントが読めないパーティションを
静かに飛ばせるのも、この判定がマウント時にあるからです。

`umount`は、そのボリュームに開いているファイルハンドルが残っている間は`Busy`で
断ります。ハンドルの後始末を利用者に決めさせるためです。

## マウントはファイルシステムを保持しない

`Mount`が持つのはボリューム識別子（`VolumeId`）とブロック範囲だけで、開いた
`FatVolume`は持ちません。開いているファイルもライブラリのハンドルではなく、
`VolumeId`・ボリューム内のパス・オフセットだけを持ちます。

各操作は「パスからマウントを解決 → レジストリからデバイスを借りる →
ボリュームを開く → 処理 → 全部捨てる」を毎回行います。これにより:

- 同じディスクの`p1`と`p2`を同時にマウントできます。どちらもドライバを
  所有しないので所有権の衝突が起きません
- USBの再スキャンがセッションを差し替えても、古いセッションを指したままの
  ポインタがファイルシステム側に残りません
- ファイルハンドルが媒体の再bindを跨いで生き残ります。ボリューム識別子・パス・
  オフセットは再bind後も同じ意味を持つためです

代償として、操作のたびにブートセクタを読み直しルートからパスを辿ります。
これを吸収するのが下記のセクタキャッシュです。最適化は実測してから行います。

## 層構成

```text
VFS（src/fs/vfs.rs：パス解決、マウント表、ファイルハンドル）
  └─ hadris-fat（FAT12/16/32の解析）
       └─ BlockStream（src/fs/stream.rs：byte単位I/O＋セクタキャッシュ）
            └─ PartitionBlockDevice（src/fs/partition.rs）
                 └─ BlockDevice（[STORAGE.md](STORAGE.md)）
```

`BlockStream`はライブラリが要求するbyte単位の`Read`/`Seek`をブロックI/Oへ
橋渡しする唯一の場所です。ファイルシステム側がLBAを計算することも、
ブロックデバイス側がbyteオフセットを見ることもありません。

セクタキャッシュはマウントあたり4 KiB（8ブロック）で、散らばった複数の
ブロックではなく**連続した1つの区間**を保持します。クラスタチェーンの追跡も
ファイルデータの読み出しも前方へ進むので、同じ容量なら連続区間の方が当たります。
区間の先頭は区間長の倍数に揃えるので、同じブロックは常に同じ区間に対応します。

キャッシュバッファは64 byte境界に宣言してあります。SDのIDMACが直接書き込めるので、
`sdmmc.rs`のステージング用コピーを経由しません（[`STORAGE.md`](STORAGE.md)）。

## 媒体の同一性（fingerprint）と世代

「これは何という媒体か」には答えられません。USBの`iSerialNumber`は任意で、
空の製品も全個体同じ値の製品もあります。SCSIのVPDページも任意です。MBRの
disk signatureとFATのvolume serialは32 bitで、0のことも多く、イメージを複製すれば
そのまま複製されます。パーティションエディタが「UUID」と呼ぶことがあっても
128 bit UUIDではありません。

答えられるのは「**これはさっきと同じ媒体か**」です。答えた情報源すべてを容量・
パーティション表・ボリュームのブートセクタと一緒に畳み込み、どれか1つでも違えば
別の媒体と判定します。逆は成り立ちません（同一内容の複製は区別できません）。
読み出しにおいて完全な複製同士は交換可能なので、これは受け入れています。

情報源（`src/fs/fingerprint.rs`）:

| 情報源 | 内容 | 備考 |
| --- | --- | --- |
| `cid` | SDカードのCID全体 | 製造者・製品名・リビジョン・シリアル・製造年月。活性化時に取得済みなのでバス通信は不要 |
| `inquiry` | SCSI標準INQUIRYのベンダ／製品／リビジョン文字列 | 先頭8 byteは個体差で変動することがあるので除く |
| `serial` | VPDページ`0x80`（Unit Serial Number） | 任意。答えないUSBメモリは多い |
| `devid` | VPDページ`0x83`（Device Identification） | 任意 |
| `mbr` | MBRのdisk signatureとパーティション表（440..510） | 前段のブートコードは含めない |
| `boot` | マウントするパーティションの先頭セクタ（3..64） | OEM名とBPB。周囲のブートコードは含めない |

`mounts`は各マウントの世代と、fingerprintのdigest、**どの情報源が答えたか**を
表示します。`size only`は容量以外に何も答えなかったという意味で、一致しても
ほとんど何も保証しません。これを表示するのは、digestだけを出すと情報源が
何であれ同じだけ確かそうに見えるからです。

確認のタイミングは2段階です。

- **操作のたび**: 容量とブロック長だけを比較します。デバイス解決の時点で
  USBはREAD CAPACITY済み、SDは通信不要なので、これは無料です。同じスロットに
  違う容量のカード、という一番ありがちな入れ替えを捕まえます
- **`fsverify`**: 全情報源を取り直して比較します。1デバイスあたり数コマンド
  かかるので明示操作です。変化していればマウントを外し、開いているファイルは
  以後失敗します。デバイスが不在、または identity を取得できなかった場合は
  **マウントをそのまま残します**。どちらも「別の媒体である」ことを示さないので、
  もうすぐ復帰するハンドルを捨てることになるためです

### 物理的な抜き差し

fingerprintが覆えない半分です。同じUSBメモリを抜いて挿し直せば identity は
完全に一致しますが、その間 媒体は無くなっており、開いているハンドルが
それを跨いで生き残ってはいけません。

そこで`UsbHost::connection_epoch`（[USB.md](USB.md)）をマウント時に記録し、
**identityより優先して**判定します。進んでいれば`DISCONNECTED since mount`として
マウントを外します。identityが一致するのは「同じ媒体が戻ってきた」ことであって
「一度も離れなかった」ことではないためです。

この検査は整数2つの比較なので、`fsverify`だけでなく**操作のたび**に行います。

epochは**ポート単位**です。ハブから1本抜いても、同じハブに挿さっている他の
デバイスのマウントはそのまま残ります。ただしルートで起きた事象（USB-Aの
ケーブル自体が抜けた等）はハブごとバス全部を持ち去るので、全ポートに効きます。

### バス上の位置

マウント時に**バス上の位置**（直結ポートかハブの何番ポートか）も記録し、操作の
たびに照合します。これはレジストリの記録を読むだけでバス通信が無いので無料です。
位置が変わっていれば`media changed`になります。デバイスを別のポートへ挿し替えた
場合がこれで、物理的な移動なので正しい挙動です。

`usbM`が繋がっている間動かなくなってからは、この検査は「同じ番号が別の位置の
デバイスを指すようになった」ことではなく「このデバイスが動かされた」ことを
捕まえる検査になっています。

### rescanを跨いでもマウントは生き残る

`Suspended`という状態は持ちません。マウントはFATボリュームもライブラリのハンドルも
持たないので、rescanがバスを作り直してもマウント表は何も失わないためです。
保存して復元する対象がそもそも存在しません。

転送が失敗したセッションは`temporarily unavailable`を返し、ハンドルは破棄しません。
`usbrescan`でセッションが戻れば同じハンドルから読み出しを再開できます。
「別媒体になった」「持ち去られた」の判定はfingerprintとconnection epochが担います。

理由の区別（`Recovery`／`Manual`／`PowerRecovery`／`PhysicalConnectionChange`）は
[USB.md](USB.md)にあります。

## パスの規則

- UTF-8、絶対パスのみ。**VFSはカレントディレクトリを持ちません**。持つのは
  シェルで、相対パスはシェルが絶対パスへ直してから渡します（`fs::path::join`）。
  VFSに入れると、入ってくるパスが正規化済みの絶対パスであるという不変条件が
  消え、利用者が増えたときに「誰のカレントディレクトリか」を決めることになります
- 正規化はVFSの入口で1回だけ行います。`//`、`.`、末尾の`/`を畳み、`..`を解決します
- 全体・1要素とも最大255 byte。FATとexFATで上限が違うため、媒体によって
  受理されるパスが変わらないようVFS側で固定しています
- ルートを越える`..`は`EscapesRoot`で拒否します。ルートで止めないのは、
  そう書いた呼び出し側は別の場所を意図しているためです
- 制御文字と`" * : < > ? \ |`を含む要素は拒否します（FAT/exFATの予約文字）
- 名前の比較はASCIIの大文字小文字のみ無視します。それ以外はコードページと
  exFATのup-caseテーブル次第で、ここで推測するとボリューム自身の答えと食い違います

## exFAT

読み出しのみです。`mounts`がボリュームごとに`FAT`／`exFAT`を表示します。

書き込みを実装しない理由は2つあります。採用した`hadris-fat`のexFATは
**明示的に不安定なプレビュー**で、作者自身が「かけがえのないデータには
推奨しない」と書いています。そしてこのファームウェアが到達できるexFAT
ボリュームはSDとUSBだけで、どちらにせよ方針上 読み取り専用です。書き込み経路を
足しても書く先がありません。`/`はこちらのフォーマッタが作るFAT16です。

`ExFatVolume`は`FatVolume`とは別の型で、共通のtraitもありません。VFSは
両者をenumで持ち、`ls`／`open`／`read`／`write`の4箇所で分岐します。
1つのtraitに包むと、扱いがかなり違う2つのファイルシステム（片方は書けて
片方は書けない、片方はパスを自分で解決し片方はしない）の上に抽象を
でっち上げることになります。

読み出し経路の実装上の違い:

- exFATはパス解決を自前で持つので、VFS側でコンポーネントを辿りません
- exFATのreaderは**シークできます**。FATのreaderはできないので、FATの
  オフセット指定読み出しは手前を読み捨てる分だけオフセットに比例した
  コストがかかりますが、exFATはシーク1回で済みます
- サイズは`valid_data_length`（実データ長）を使います。`data_length`
  （確保済み長）ではありません
- タイムスタンプのUTCオフセットは**無視します**。exFATは記録できますが
  FATにはその場所が無く、こちらはFATへローカル時刻を書いています。
  exFAT側だけ変換すると、同じPCが書いた2枚のカードが一覧上で食い違います

プレビュー実装の制限（作者記載）: allocation bitmapとupcaseテーブルの
断片化、ディレクトリの拡張、クラスタ境界をまたぐentry setの一般配置、
TexFAT、修復には対応しません。このうち読み出しに影響し得るのは
**断片化したupcaseテーブル**（名前比較に使う）と**クラスタ境界をまたぐ
entry set**（長い名前で起こり得る）です。実媒体で踏んだ場合は該当ファイルの
読み出しが失敗します。

## 読み書きの保証

| マウント | 形式 | 読み | 書き |
| --- | --- | --- | --- |
| `/`（`/tmp`を含む） | FAT16 | 可 | 可 |
| `/vol/sd0pN` | FAT／exFAT | 可 | 不可（全Stageで読み取り専用） |
| `/vol/usb0pN` | FAT／exFAT | 可 | 不可（全Stageで読み取り専用） |

exFATはマウントの読み書き方針とは別に、形式として読み取り専用です。

`/tmp`へ一時ファイルを置くのはポリシーであり、書き込み権限はRAMルート全体に
あります。ただし`/tmp`のディレクトリ自体と`/vol`の予約名前空間は変更できません。

読み取り専用は**2層で**担保します。マウントの`MountMode`が`open`と`create_dir`の
時点で拒否し、さらにSD／USBのブロックアダプタが`write_blocks`をコマンド発行前に
`WriteSuppressed`で失敗させます。`write /vol/sd0p1/X hello`で実機から確認できます。

## 書き込み

### オープンモード

3つだけです。それぞれが、下のライブラリが実際にできることに対応します。

| モード | 意味 |
| --- | --- |
| `Read` | ファイルは存在していなければならない。書かない |
| `Truncate` | 無ければ作る、有れば空にする。先頭から書く |
| `Append` | 無ければ作る。末尾に書く |

排他作成モードや「途中を上書き」するモードはありません。ライブラリのwriterは
ファイルの先頭か末尾から前へ進むだけでシークできないので、それらは下の層が
守れない約束になります。**提供してから使う時点で断る**のではなく、最初から
提供していません。

書き込める位置は2つだけです。置き換えるために開いたファイルの先頭と、末尾です。
それ以外は`can only write at the start or the end of a file`で断ります。読み直して
書き直すことで模倣はしません。それは失敗の仕方が違う別の操作で、ここで必要な
ものではありません。

`Truncate`の最初の書き込みだけがファイルを空にし、2回目以降は末尾に足します。
そうしないと、呼び出しのたびに前回書いた内容を捨てることになります。

### コミット

書き込みは3段階で、どれが失敗しても書き込みの失敗です。

1. `write` — クラスタへバイトを置く
2. `finish` — ディレクトリエントリにサイズとタイムスタンプを確定させる。
   **これをしないとバイトは媒体上にあるのに誰も指していません**
3. `sync` — FATとディレクトリを媒体へ出す

### タイムスタンプ

RTC（RX8130CE）から取ります。RTCが保持しているのはUTCなので
（[RTC.md](RTC.md)）、`wall_clock::local_now`で既定タイムゾーンのJST（`+0900`）へ
変換した値を書きます。FATにはオフセットを記録する場所が無く、これらのボリューム上の
タイムスタンプは既に「書いた側の時計」を意味するので、UTCのまま書くとPCが同じカードへ
書いたファイルと9時間ずれて並びます。

将来タイムゾーンを変更できるようになった場合も、FATにはその時点のローカル時刻を
書きます。証明書検証が使うUnix秒（`wall_clock::unix_time_utc`）はUTCのままで、
この変換とは別経路です。

RTCは**操作ごとに1回**、書き込みを始める前に読みます（`src/fs/clock.rs`）。
ライブラリは`&'static`なプロバイダしか受け取れず、またソフトウェアI2Cを
ディレクトリエントリの書き込みの内側から叩くのは避けたいためです。1回の操作で
書かれるエントリは全て同じタイムスタンプになり、これは書き込みにかかった時間だけ
ずれた複数の読み取りより安上がりで、かつ正確です。

RTCが未設定・読めない場合は日付と時刻に**0を書きます**。これは日付ではなく、
FATが「タイムスタンプ無し」に使う値です。1980-01-01を書くのは主張であり、
しかも嘘になります。`ls`はこれを`(no time)`と表示し、日付として解釈しません。

書き込んだ時刻は`ls`で確認できます。

### 流し込み（`write_stream`）

`Vfs::write`はハンドルの位置に書くもので、**呼び出しのたびにボリュームを開き、
ディレクトリを辿り、`FileWriter`を作り直し、エントリを確定してsyncします**。
ハンドルがライブラリのカーソルを持たない設計（上記「マウントはファイルシステムを
保持しない」）の帰結で、それがrescanを跨いで生き残れる理由でもあります。

このコストは**呼び出し回数**に付きます。同じファイルを半分の大きさに区切って書くと
所要時間はおよそ倍になります。

`FileWriter::new_append`がファイルの末尾をFATチェーンを辿って探すため、1回あたりの
コスト自体もファイルサイズとともに増え、合計には`n^2`の項があります。ただし
**8 MiBのRAMディスクでの実測では見えません**——サイズを倍にすると時間も倍で、
このクラスタ数では1回あたりの固定コストが走査を覆い隠します。`write_stream`が
省くのはその固定コストのほうです。

`Vfs::write_stream`は1回の呼び出しの内側でボリュームと`FileWriter`を開いたままに
します。writerは1回だけ作り、`write`を繰り返す——ライブラリが想定する使い方です。
1回の操作の内側なら生き残る必要はありません。`ls`も`cat`も既に同じことをしています。

実測（`fill <path> <KiB> [chunk] [repeat]`、`/tmp`）:

| 経路 | サイズを倍にする | chunkを4分の1にする |
| --- | --- | --- |
| `write_stream` | 約2倍 | ほとんど変わらない |
| `write`の繰り返し（`repeat`） | 約2倍 | 呼び出し回数に比例して増える |

`write_stream`が**書き込み単位に依存しない**のが実用上の違いです。ネットワークからの
流し込みは1ブロック512 byteで届くので、旧経路ではその粒度がそのままコストになります。

**body（クロージャ）が途中で失敗しても、届いた分は確定させます。** 確定させないと
どのディレクトリエントリからも辿れないクラスタが媒体上に残り、辿れない以上
取り戻す手段もありません。確定させておけば、書きかけを見ることも、削除して
容量を戻すこともできます。どちらにもファイルが存在している必要があります。
sinkを止めた理由は`StreamWrite::interrupted`で返します。

### 削除と改名

`Vfs::remove_file`／`remove_dir`／`rename`があります。RAMルート全体で使え、
読み取り専用マウントとexFATは先に断ります。

- 削除は**ファイルとディレクトリで別の入口**です。`rm`はディレクトリを取らず、
  `rmdir`はファイルを取りません。ライブラリはどちらも消せますが、打ち間違いで
  消えた空ディレクトリは最初から無かったものと見分けがつきません
- ディレクトリは**空のときだけ**消せます。再帰削除は、途中で失敗すると誰も
  頼んでいない形が残る別の操作です
- **開いているハンドルがあるファイルは`Busy`で断ります。** `umount`が
  ビジーなマウントを断るのと同じ理由です
- 改名で動くのは**ディレクトリエントリだけ**で、クラスタチェーンはその場に
  残ります。それが安い理由であり、同時に**ボリュームを跨げない**理由でもあります。
  跨ぐならバイトのコピーになり、途中で失敗したときの後始末が別物になります。
  ボリュームが同じかどうかは、どちらかが書き込み可能かより**先に**判定します。
  RAMルートと外部媒体のあいだは、外部媒体の読み取り専用方針とは別に
  `cannot move between volumes`です
- 移動先が既にある場合は断ります。置き換えるなら削除と改名の2手になり、その間
  どちらの名前でも辿れない瞬間ができます。いつその危険を冒すかは呼び出し側が
  決めるほうが適切です

### 未回収のクラスタ

`Truncate`で既存のファイルを短い内容に置き換えると、末尾より後ろのクラスタが
解放されないままになる可能性があります。破損ではありませんが、容量は減ります。
RAMルートは起動ごとに作り直すので影響は1回のセッション内に限られます。

### ディレクトリの作成

`Vfs::create_dir`はFATのみです。exFATと読み取り専用マウントは、ファイルの
書き込みと同じ判定で先に断ります。

**作るのは最後の要素だけ**です。親が無ければ`not a directory`で失敗します。
ファイル作成（`create`）と同じ規則にしてあります。親をまとめて作る`mkdir -p`
相当は、打ち間違いをそのままディレクトリ階層にしてしまうので持ちません。

すでに同じ名前がある場合は`already exists`です。ライブラリの`create_dir`が
新しいディレクトリの中に`.`と`..`を書くので、できたディレクトリはPCからも
そのまま読めます。

## RAMディスクの内容

RAMディスク全体を起動ごとにFAT16でフォーマットし直し、`/tmp`と`/vol`を作ります。
読み出し検証用のファイル3つは`/tmp`へ書き込みます（`src/fs/seed.rs`）。内容は
リセットで消えます。

| ファイル | 検証する対象 |
| --- | --- |
| `README.TXT` | 8.3短名、単一クラスタ |
| `Hello World.txt` | LFN。`HELLOW~1.TXT`と表示されたらLFNチェーンを組み立てていない |
| `CHAIN.TXT` | 複数クラスタ。各行に自分が入っているクラスタ番号を書いてあるので、チェーンを見失うと**もっともらしい途中まで**ではなく明らかに誤った番号が出る |

これらはファイルシステムライブラリを通さず、ディレクトリエントリとFATを
直接書いて作ります。同じライブラリの書き手と読み手が互いに整合しても
独立した読み出し検証にならないことが理由です。

## シェルコマンド

| コマンド | 内容 |
| --- | --- |
| `mount` | マウント一覧（`mounts`と同じ） |
| `mount <ram\|sd0pN\|usbMpN>` | ボリュームをマウント。`ram`は既に`/`にあり、SDとUSBは常に読み取り専用 |
| `umount <mount point>` | アンマウント。`/`は予約パス、ほかは開いているファイルがあれば`Busy`で拒否 |
| `automount [on\|off]` | USBの自動マウントの状態表示と切り替え。既定はon |
| `mounts` | マウント一覧 |
| `cd [<path>]` | カレントディレクトリを移す。移動先の存在と種別を確認する。引数なしは`/` |
| `pwd` | カレントディレクトリを表示 |
| `ls [-l] [-a] [<path>]` | ディレクトリ一覧。既定は名前だけを名前順で桁詰め。`-l`で種別・サイズ・更新日時、`-a`で`.`と`..`も出す。引数なしはカレントディレクトリ |
| `cat <path> [offset]` | ファイルを表示。読めたbyte数をディレクトリエントリのサイズと照合し、不一致なら`SHORT READ`と出す |
| `fsopen [<path>]` | ファイルをコマンドを跨いで開いたまま保持（読み取り専用）。引数なしで保持中の一覧 |
| `fsread <slot> [bytes]` | 保持中のハンドルから読み、**結果だけ**を出す |
| `fsclose <slot>` | 保持中のハンドルを閉じる |
| `write <path> <text>` | 1行のテキストでファイルを作る／置き換える |
| `append <path> <text>` | ファイルに1行足す。無ければ作る |
| `mkdir <path>` | ディレクトリを作る。作るのは最後の要素だけ |
| `rm <path>` | ファイルを削除。開いていれば`Busy`、ディレクトリなら拒否 |
| `rmdir <path>` | 空のディレクトリを削除 |
| `mv <from> <to>` | 改名・同一ボリューム内の移動。移動先が既にあれば拒否 |
| `fill <path> <KiB> [chunk] [repeat]` | 既知のパターンを書いて所要時間を出す。書き込み経路の計測用 |
| `fsverify` | 全マウントの媒体を、マウント時のfingerprintと突き合わせる |

パス引数は`/`で始まらなければカレントディレクトリからの相対パスとして解決します。
解決はシェル側の1箇所（`split_argument`の直後）だけで、VFSへ渡るのは常に
正規化済みの絶対パスです。規則の詳細は[CONSOLE_SHELL.md](CONSOLE_SHELL.md)の
「カレントディレクトリとパス引数の解決」にあります。

`cat`のサイズ照合は、クラスタチェーンを途中で見失った読み手が「もっともらしい
先頭部分」を出して成功したように見えるのを防ぐためです。

空白を含むパスはダブルクォートで囲みます（`cat "/tmp/Hello World.txt"`）。
FATの長い名前は普通に空白を含むので、位置だけで引数の境界を決める規則は作れません。
シェル側の規則は[CONSOLE_SHELL.md](CONSOLE_SHELL.md)にあります。

## 未対応

- SD／USBへの書き込み（全Stageで読み取り専用）
- exFATへの書き込み（上記のとおり実装しない）
- rescanを跨いだhandle rebindと`Suspended`状態（同Stage 3）
- SDカードの自動マウント（挿抜検出線が無く、挿さっているかはコマンドの
  タイムアウトでしか分からないため。USBだけが自動マウントの対象です）
- truncate（`Truncate`で開き直すことによる置き換えはできます）
- 破損イメージの拒否の検証（ホストテストを別タスクへ保留中。検査コードは
  書いてあるが壊れたイメージには通していない）
